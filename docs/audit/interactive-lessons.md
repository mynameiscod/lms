# Interactive Lessons
**Completion:** 78%  |  **Priority:** P1  |  **Business Impact:** High

## Purpose & Business Goal
Duolingo-style gamified programming lessons made of **7 scene types** (story, code_demo, drag_drop, quiz, fill_blank, code_run, summary). Authored in a rich builder or generated by AI (Claude), played in an animated viewer with XP, per-scene attempts, and pass/fail scoring. These are the marquee learning artifact — both hand-authored by instructors and auto-generated per personalized day. Live code (`code_run`) executes through self-hosted Piston.

## Primary Users & Roles
- **TENANT_ADMIN / INSTRUCTOR** — build/AI-generate/publish lessons.
- **STUDENT** — play lessons, earn XP, run code.
- **SUPER_ADMIN** — cross-tenant.

## Dependencies & Connected Modules
- **Content Library** — each lesson links to a `LearningContentLibrary` item (`contentLibraryId` ⇄ `conceptLessonId`); publish syncs both.
- **Enrollment/Day plans** — lessons attached as day items; progress carries `enrollmentId`+`dayNumber`.
- **Day-content generator** — reuses `generateLesson()` for lazy day gen.
- **Piston** (Docker) for `code_run`; **Anthropic Claude** for generation.

## Entry / Exit Points
`GET /interactive-lessons/templates`, `POST /generate-ai`, `GET /` (filters lang/concept/difficulty/published), `POST /`, `GET/PUT/DELETE /:id`, `GET /:lessonId/progress-admin`, `POST /execute` (Piston), `GET /:lessonId/progress`, `POST /:lessonId/progress/scene`, `POST /:lessonId/complete`. All auth+tenantResolver; **no roleGuard on any route**.

## Database Tables & Relationships
- `interactivelessons` — `(tenantId,language,concept)`, `(tenantId,isPublished)`; embedded scenes with per-type sub-schemas.
- `lessonprogresses` — unique `(tenantId,studentId,lessonId)`; `(tenantId,lessonId)`, `(tenantId,enrollmentId)`.

## Events / Notifications / Emails / WhatsApp
None. `completeLesson` increments `completionCount` but emits no event/notification and does **not** update the CurriculumEnrollment day-completion (the `enrollmentId`/`dayNumber` link is stored but not acted on) — a gap in curriculum integration.

## AI Features (which model, or "None")
- **AI lesson generation** (`lessonAIService.generateLesson`) — **Claude**, default `claude-sonnet-4-6`, selectable Opus 4.7 / Haiku 4.5. System prompt enforces exactly 7 scenes; 24h in-memory cache keyed by concept|language|difficulty|model. Builder shows per-model cost estimates.
- `code_run` grading via Piston (not AI); HTML/CSS graded by markup structure match.

## Validation Rules & Edge Cases
- Create requires title/language/concept; `totalXp` computed from scenes; `passingScore` default 60.
- Score = passed interactive scenes (quiz/fill_blank/drag_drop/code_run) / total interactive scenes × 100.
- Piston: Java filename must match public class; generous 15s run limit (compile-in-run cold start); compile-error surfacing; output normalized (CRLF/trailing space).
- **Critical edge/security gaps:**
  - `POST /:lessonId/progress/scene` accepts client-supplied `xpEarned` **without validating against `scene.xpReward`** → XP can be forged.
  - No route-level roleGuard → any authenticated user can create/delete lessons and call `/generate-ai` (uncapped Claude spend) and `/execute` (no rate limit → Piston DoS).
  - No `ObjectId` validation on `:id`; no scene-structure validation; no input sanitization (XSS risk in scene text).
  - `code_run` test cases stored but not shown to student; simulation mode only recognizes ~9 algorithms.

## Technical Debt / Performance / Security / Scalability
- **Top risks:** XP forgery + missing authz + uncapped AI spend + Piston DoS — all fixable in ~1 week and should be P0-within-P1.
- In-memory AI cache doesn't survive restart or scale horizontally.
- Simulation fallback silently produces untrustworthy pass/fail if Piston is down — should hard-fail or flag.

## Suggestions & AI Opportunities
- Immediate: validate `xpEarned ≤ scene.xpReward` server-side; add roleGuard (`manage_interactive_lessons`, admin-only `generate-ai`); rate-limit `/execute` + `/generate-ai`; sanitize scene text.
- Wire `completeLesson` to mark the enrollment day item complete (close the curriculum loop).
- Track AI spend in `AiUsage` per generation; add per-tenant monthly cap.
- AI opportunity: adaptive difficulty (regenerate a harder/easier scene on repeated fail); auto-hint generation; per-student name interpolation (`{{name}}` already in schema but not applied in viewer).
