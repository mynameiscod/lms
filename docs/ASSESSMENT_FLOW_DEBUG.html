Assessment Flow: Founder's Debug Map

Every step of the assessment funnel, decoded so you can see what the user experiences, what happens behind the scenes, how it breaks, and exactly where to look — without being a developer.

👤 User sees — the candidate's experience
⚙️ Behind the scenes — what the system does
✕ If it breaks — the failure modes
🔎 Where to look — how to diagnose

The flow, step by step

1

Landing & Registration

👤 User sees

Branded page → fills name, email, profile (year/professional), primary language, target role, resume (optional).

⚙️ Behind the scenes

Creates an AssessmentSubmission (status registered) and, if a resume is uploaded, parses it to feed the exam design.

✕ If it breaks
  • Wrong tenant in URL → "not found"
  • Resume upload error (parse) → 500 (non-blocking)
🔎 Where to look
  • Candidate appears as "registered" in the Assessment Candidates dashboard
  • Browser console for the resume 500
2

WhatsApp OTP — send most common break point

👤 User sees

"Enter the 6-digit code sent to <number> on WhatsApp." If the send fails, a yellow "Dev mode: your code is …" box appears instead.

⚙️ Behind the scenes

sendOtp() calls the WhatsApp Cloud API with template cb_otp. It tries the CRM WhatsApp first, then falls back to Platform Settings WhatsApp.

✕ If it breaks
  • Expired token → 401 / code 190
  • Number not a verified test recipient (if account is in test mode)
  • Unpaid balance / billing issue on Meta
  • Template in wrong WhatsApp account or wrong language
  • Recipient has no WhatsApp
🔎 Where to look
  • Server log keyword [assessment-otp] — shows Meta's exact error
  • "Dev mode" box = the send failed (code shown so testing isn't blocked)
  • Meta → WhatsApp Manager → number status & Billing
  • Platform Settings → Meta/WhatsApp values
3

OTP — verify

👤 User sees

Types the code → "Verify & Start Assessment."

⚙️ Behind the scenes

verifyOtp() checks the code (valid 10 min, max 5 attempts) and consumes it on success.

✕ If it breaks
  • Code expired (>10 min)
  • Too many wrong attempts (5)
  • Wrong code entered
🔎 Where to look
  • The on-screen error tells the reason
  • Resend code button issues a fresh one
4

Account creation & login delivery

👤 User sees

"We've created your CodeBegun account." Login details arrive by email & WhatsApp.

⚙️ Behind the scenes

ensureCandidateAccount() creates a STUDENT account (or safely reuses an existing one), then emails the login (username + temp password) + best-effort WhatsApp.

✕ If it breaks
  • Email already exists (e.g. an old staff account) → reused, not re-created
  • Email not configured → welcome email fails
  • No email captured → no account
🔎 Where to look
  • Log keyword [assessment-account]
  • The candidate's email inbox (+ spam)
  • Test the mailbox via Platform Settings → "Send test email"
5

AI exam design & generation

👤 User sees

The exam loads with questions tailored to their profile.

⚙️ Behind the scenes

Claude designs a per-candidate blueprint and writes items; code questions are verified on Piston. A pre-warmed question bank backs it.

✕ If it breaks
  • No AI key → generation fails
  • Empty question bank → exam 503
  • Piston down → code items can't verify
🔎 Where to look
  • Assessment Admin → question bank count & "Generate with AI"
  • Platform Settings → Anthropic API key
6

Taking the exam & scoring

👤 User sees

Answers adaptive questions on any device; then "Submit."

⚙️ Behind the scenes

Staged delivery adjusts difficulty on the running score; anti-cheat guards apply. On submit, responses are scored across the skill dimensions.

✕ If it breaks
  • Rare — network drop mid-exam
🔎 Where to look
  • Candidate shows "submitted" with a readiness score in the dashboard
7

AI roadmap & auto-enrolment

👤 User sees

Their personalized plan on the Result page; a free preview is ready.

⚙️ Behind the scenes

Matched to a mentor master-track, cloned & personalized; auto-enrolled as a preview; synced to the CRM as a lead.

✕ If it breaks
  • No published master-track / curriculum → candidate not enrolled
  • Roadmap AI fails → generic plan
🔎 Where to look
  • Log keyword [assessmentEnroll]
  • A published Learning Curriculum must exist for the tenant
8

Result page & conversion

👤 User sees

Readiness gauge, salary potential, gap map, roadmap → "Log in & start free" + "Talk to a mentor".

⚙️ Behind the scenes

Public result endpoint returns the scored result; buying triggers the Razorpay unlock; mentor route creates a CRM concern/lead.

✕ If it breaks
  • Razorpay keys not set → unlock button hidden
  • Result fails to load → roadmap missing
🔎 Where to look
  • Platform Settings → Razorpay keys + price
  • Assessment Candidates dashboard → unlock action

Deep-dive: why OTP might not arrive

The send path (and its two fallbacks)

sendOtp()→ Try CRM WhatsApp token→ if 401/fail → Try Platform Settings WhatsApp→ if fail → Show Dev-mode code on screen

Key rule: if the yellow "Dev mode: your code is …" box shows, the WhatsApp send failed — the code is displayed only so testing isn't blocked. If it's not shown, Meta accepted the message (a delivery, not a sending, problem).

SymptomMost likely causeFix
Dev-mode code shows; log = 401 / code 190The token in use is expiredEnsure Platform Settings token is a permanent System-User token; refresh the CRM one or rely on fallback
No code on WhatsApp, no dev box, no errorMeta accepted it but didn't deliver — number not a verified test recipient while account is in test modeAdd the number to Meta's verified list, or add a payment method to go production
Meta error: template does not existTemplate in the wrong WhatsApp account or wrong languageCreate cb_otp (Authentication) in the WABA that owns the sending number; match the language
Meta error: recipient not in allowed listTest number can only message verified recipientsAdd payment method → production (message anyone)
Works for one number, not anotherOnly the first number is verified (test mode)Go production, or verify each test recipient

Your 4 dashboards to check anything

1 · Assessment Candidates dashboard

See every candidate's live stage — registered → mid-exam → submitted — with readiness, roadmap and an unlock action. Your first stop to see "did this person get through?"

2 · Platform Settings

All keys + test buttons: "Send test email", "Test IMAP", and the WhatsApp/OTP config. Confirms integrations are alive without a developer.

3 · Meta WhatsApp Manager

Number status & quality, message templates, Insights (delivery) and Billing. This is where WhatsApp delivery + payment issues surface.

4 · Server logs (ask your dev)

Grep keywords: [assessment-otp], [assessment-account], [assessmentEnroll]. Each prints the exact reason a step failed.
