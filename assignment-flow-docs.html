2. Admin: Creating an Assignment
2.1 Creation Steps
  1. Admin goes to Manage Assignments → Create
  2. Fills in Basic Info: Title, Description, Instructions (rich text)
  3. Chooses Type (Coding / MCQ / Theory / SQL / Web / File Upload)
  4. Sets Difficulty: Beginner / Easy / Medium / Hard / Expert
  5. Configures Access Control: Everyone / Batch-wise / Individual students
  6. Sets Schedule: Start date, Due date, Late submission deadline
  7. For Coding → adds Test Cases (input/expected output, visible vs hidden, weight/points)
  8. For Coding → adds Starter Code per language (optional boilerplate)
  9. For MCQ → adds Questions and Options, marks correct answers
  10. Configures Settings: Max attempts, time limit, show/hide results, plagiarism check
  11. Saves as Draft → reviews → clicks Publish

4. Student: Assignment List Page
  1. Student opens My Assignments from sidebar
  2. API call: GET /api/v1/assignments/student/list
  3. Backend filters: status = published + accessible to this student (batch / individual)
  4. Returns assignments with their submission status for that student
  5. UI shows cards with: Title, Type badge, Due date, Points, Status badge (Not Started / In Progress / Submitted / Graded)
  6. Student clicks a card → goes to Assignment Workspace
✅ The student only sees assignments that are: published, within access scope, and have not passed late submission deadline.
5. Student: Starting & Working on an Assignment
5.1 Instructions Page (Before Start)
  1. Student arrives at workspace → sees Instructions Page (not the editor yet)
  2. Page shows: title, description, type, difficulty, total points, time limit, attempt info
  3. Shows important notes (auto-save, max attempts, time limit warning)
  4. Student clicks Start Assignment
  5. API call: POST /api/v1/assignments/:assignmentId/start
  6. Backend creates a Submission document with status: IN_PROGRESS and records startedAt
  7. If submission already exists (IN_PROGRESS) — returns the existing one (resume)
  8. Instructions page disappears → editor/workspace loads
5.2 Workspace — Coding Assignment

Left Panel — Problem

  • Problem description (rich text)
  • Instructions
  • Visible test cases (input + expected output)
  • Output tab (after Run)

Right Panel — Editor

  • Language pills (JS / Python / Java…)
  • Monaco code editor (VS Code-like)
  • Run button → executes visible tests
  • Submit button → executes all tests
  • Auto-save every 30 seconds
5.3 Language Switching (Coding)
  1. Student clicks a different language tab (e.g. Java → Python)
  2. Current code is saved to memory for the current language
  3. Current code is also auto-saved to server (POST /submissions/:id/save-code)
  4. Editor remounts with the saved code for the new language (or starter code, or blank)
  5. Switching back to Java restores what the student had written in Java
Monaco Editor uses key={selectedLanguage} to force a full remount on language switch — this ensures the editor always shows the correct code and not a stale cached view.
5.4 Auto-Save

Every 30 seconds, the workspace silently calls POST /submissions/:id/save-code. The backend saves the code and adds a snapshot to codeSnapshots[] (last 50 kept). This allows code playback and prevents data loss.

5.5 Workspace — MCQ Assignment
  1. Shows all questions with radio button options
  2. Student selects answers
  3. Progress bar shows how many answered
  4. Clicks Submit → calls POST /submissions/:id/submit-mcq
  5. Backend instantly checks each answer against isCorrect flag
5.6 Workspace — Theory Assignment
  1. Shows a large textarea for long-form answer
  2. Student types their answer
  3. Clicks Submit → calls POST /submissions/:id/submit-theory
  4. Instructor grades manually later

7.2 What Happens on Submit (Coding)
  1. Backend fetches submission + assignment (with all test cases)
  2. Runs code against every test case (visible + hidden) via Piston
  3. For each test case: records passed, executionTime, memoryUsed, actualOutput, error
  4. Hidden test cases: input, expectedOutput, actualOutput set to "" in response (student can't see them)
  5. Calculates autoScore = (earnedWeight / totalWeight) × totalPoints
  6. Checks if past due date → applies lateSubmissionPenalty %
  7. Sets isPassing = finalScore >= passingPoints
  8. Generates a shareToken (UUID) for LinkedIn share feature
  9. Sends confirmation email to student
  10. Status set to SUBMITTED (or LATE if past due date)
7.3 Submit MCQ Flow
  1. Frontend sends array of {questionIndex, selectedOptionIndex}
  2. Backend checks each against isCorrect flag on assignment's mcqQuestions
  3. Each answer gets isCorrect + pointsEarned
  4. autoScore = sum of all pointsEarned
  5. Status → SUBMITTED, redirect to results
7.4 Submit Theory Flow
  1. Frontend sends theoryAnswer (text)
  2. Saved to submission, autoScore = 0 (no auto grading)
  3. Status → SUBMITTED
  4. Instructor grades manually
8. Scoring & Grading
8.1 Score Calculation Formula
// Coding / SQL / Web
autoScore  = ( earnedWeight / totalWeight ) × totalPoints
totalScore = autoScore + manualScore
finalScore = max(0, totalScore - penaltyApplied)
percentage = (finalScore / totalPoints) × 100
isPassing  = finalScore >= passingPoints

// Late penalty (applied if submittedAt > dueDate)
penaltyApplied = totalScore × (lateSubmissionPenalty / 100)

// MCQ
autoScore = sum of pointsEarned for each correct answer
8.2 Submission Status Lifecycle
NOT_STARTED
Assignment visible, student hasn't clicked Start
IN_PROGRESS
Start clicked, submission created, timer running
SUBMITTED
Student submitted. Awaiting manual grading (theory/file)
LATE
Submitted after due date. Penalty applied.
GRADING
Instructor opened for manual grading
GRADED
Final score set. Student can see full result.
8.3 Instructor Manual Grading
  1. Instructor opens Assignment Reports → Submissions
  2. Sees list of all submitted students with auto-score
  3. Clicks a submission → sees code / answer + test results
  4. For Theory/File: fills in rubric scores per criterion + feedback
  5. Can override score with manualScore
  6. Clicks Save Grade → POST /submissions/:id/grade
  7. Status → GRADED, student can now see their full result
  8. Instructor can also click Allow Re-attempt to reset and let student try again
