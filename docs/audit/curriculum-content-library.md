# Curriculum & Content Library
**Completion:** 78%  |  **Priority:** P1  |  **Business Impact:** High

## Purpose & Business Goal
The modern learning backbone. Three related systems:
1. **LearningCurriculum** — a day-wise track (default 145 days) of `topics` (each spanning a day-range with an assessment `dimension`). Doubles as an assessment-funnel **master-track** the CareerPilot funnel personalizes per candidate.
2. **LearningContentLibrary** — a reusable content pool (video / notes / tech_qa / behavioral_qa / practice_coding / practice_theory / aptitude / interactive_lesson / interactive_activity) tagged by topic/course, dropped onto days.
3. **CollegeCurriculum** — a year/semester/subject academic plan for a department (separate, college-facing).
Supporting: **DayPlan** (per-day activity list, polymorphic content+module refs), **WeekendPlan** (Sat/Sun rest/revision/project/mock), **LearningExtras** (StudentNote/Bookmark/TopicDiscussion). This is the primary authoring surface and it's cross-tenant shareable (template library).

## Primary Users & Roles
- **TENANT_ADMIN / INSTRUCTOR** — build curricula, author library content, plan days/weekends, share/clone templates.
- **STUDENT** — consumes via CurriculumEnrollment/day plans (see Enrollment module).
- **SUPER_ADMIN** — seeds master-tracks; cross-tenant template library.

## Dependencies & Connected Modules
- **Enrollment & Learning Plans** (CurriculumEnrollment, BatchOffering) consume curricula/day plans.
- **Interactive Lessons** — library `interactive_lesson` items link via `conceptLessonId`.
- **Student Progress & Personalization** — master-tracks personalized by `trackPersonalizationService`; day content lazily AI-generated by `dayContentGeneratorService`.
- **Quiz / Assignment / CodeSnippet / InterviewTemplate** — referenced as DayPlan module items (`sourceModel`/`sourceId`) via the activity bank.
- **Bunny Stream** for video hosting; local disk fallback for video/notes/thumbnails.

## AI Features (which model, or "None")
- **Lazy day-content generation** — not a manual endpoint; triggered when a student opens a personalized day (`dayContentGeneratorService.ensureDayContentGenerated`, called from `enrollmentPlanController.getStudentDayPlan`). Generates an interactive lesson + tech_qa + Piston-verified coding practice and persists them as library items. Model: **Claude Sonnet 4.6** default (via `aiClients.getAnthropic()`), configurable (Opus 4.7 / Haiku 4.5). De-dups canonical content across candidates to cut cost.
- The library/curriculum *builder* itself has no AI authoring (manual).

## Validation Rules & Edge Cases
- `totalDays` default 145 min 1; topic `startDay`/`endDay` min 1; day `dayNumber` min 1.
- Curriculum delete blocked if `enrollmentCount > 0`; content delete blocked if `usageCount > 0`.
- Multer mime/size filters; file cleanup on update/delete.
- Multipart quirk handling (empty enum → undefined; JSON-parse array fields).
- **Edge gaps:** no validation that topic day-ranges are contiguous/non-overlapping; no check that DayPlan items reference content of the same tenant; `/:id/stream` has no auth middleware (token-in-query only) — potential unauthorized video access.

- **UX:** Uses `window.confirm/alert` in places; no undo/redo on day edits.
- **Audit logs:** No AuditLog for curriculum/content edits.

## Technical Debt / Performance / Security / Scalability
- No route-level RBAC on curriculum/library routes is the top security gap — relies purely on being an authenticated tenant user.
- Video streaming from local disk (`/:id/stream`) doesn't scale and lacks auth; Bunny path is the scalable answer but coexistence adds complexity.
- Cross-tenant template library (`shared`) is a nice feature but needs abuse/version controls.
- CollegeCurriculum is architecturally orphaned from the day-plan system.

## Suggestions & AI Opportunities
- Add `roleGuard(['manage_curriculum'])` / `['manage_learning_content']` to all mutation routes; gate `/:id/stream` behind auth or Bunny signed URLs.
